<objective>
Build the YouTube RSS feed poller and yt-dlp downloader -- the core acquisition pipeline. The feed poller discovers new videos from configured channels and inserts them as DISCOVERED. The downloader checks duration, downloads qualifying videos, and transitions state to DOWNLOADED.

Purpose: This is the primary value delivery of Phase 1 -- automated YouTube content discovery and download.
Output: Working feed polling and video download with duration filtering and state tracking.
</objective>

  <name>Task 1: YouTube RSS feed poller</name>
  <files>

  <behavior>
    - test_poll_channel: Given a mock RSS response, poll_channel returns list of dicts with video_id, title, published, link, description, thumbnail
    - test_poll_channel_extracts_video_id: video_id extracted from yt_videoid field, with fallback to entry.id (yt:video:XXX format), then link (?v=XXX)
    - test_poll_channel_empty_feed: Empty feed returns empty list without error
    - test_poll_channel_network_error: Network failure raises or returns empty list with logging
    - test_discover_new_videos: Given RSS entries, new videos are inserted as Content with DISCOVERED status; existing video_ids are skipped
    - test_discover_new_videos_dedup: Video already in DB is not re-inserted
  </behavior>
  <action>
    Create src/crosspost/feeds.py with two main functions:

    1. `poll_channel(channel_id: str) -> list[dict]`:
       - Build RSS URL: `https://www.youtube.com/feeds/videos.xml?channel_id={channel_id}`
       - Use feedparser.parse(feed_url)
       - Extract per entry: video_id (with 3-level fallback: yt_videoid -> entry.id parse -> link parse), title, published, link, description (media_description), thumbnail (media_thumbnail)
       - Use loguru for logging
       - Wrap in tenacity retry (3 attempts, exponential backoff) for network resilience

    2. `discover_new_videos(engine: Engine, channel: ChannelConfig) -> list[Content]`:
       - Call poll_channel(channel.channel_id)
       - For each video: check if video_id exists in DB (SELECT by video_id)
       - If not exists: create Content row with status=DISCOVERED, video_url built from video_id
       - Return list of newly created Content objects
       - Log discovered count and skipped count

    Write tests using pytest-mock to mock feedparser.parse with sample YouTube Atom feed data (use the XML structure from research). Do NOT make real HTTP calls.
  </action>
  <verify>
    <automated>cd /root/youtube && uv run pytest tests/test_feeds.py -x -v</automated>
  </verify>
  <done>
    - poll_channel parses YouTube RSS and returns structured video data
    - discover_new_videos inserts only new videos, skips existing ones
    - All feed tests pass with mocked data
  </done>

    - test_get_metadata_uses_cookies: yt-dlp options include cookiesfrombrowser as tuple ('firefox', None, None, None), NOT string
    - test_duration_filter_pass: Video with duration <= max_duration returns should_download=True
    - test_duration_filter_fail: Video with duration > max_duration returns should_download=False
    - test_duration_filter_zero: Video with duration=0 or None passes filter (don't block unknowns)
    - test_download_video: download_video calls yt-dlp with writethumbnail=True, writeinfojson=True, correct output template
    - test_process_discovered: process_discovered_videos transitions DISCOVERED -> DOWNLOADING -> DOWNLOADED on success
    - test_process_discovered_too_long: Video exceeding duration is skipped (stays DISCOVERED, logged)
    - test_process_discovered_error: Download failure transitions to FAILED with error_message saved
  </behavior>
  <action>
    Create src/crosspost/downloader.py with:

    1. `get_video_metadata(video_url: str, cookies_browser: str = "firefox") -> dict | None`:
       - Use yt_dlp.YoutubeDL with skip_download=True, quiet=True, no_warnings=True
       - CRITICAL: cookiesfrombrowser MUST be tuple: (cookies_browser, None, None, None) -- NOT a string
       - Return info dict from extract_info(video_url, download=False)
       - Log errors, return None on failure

    2. `should_download(metadata: dict, max_duration: int = 180) -> bool`:
       - Get duration from metadata (default 0 if missing)
       - If duration == 0 or duration is None: return True (don't block unknowns)
       - Return duration <= max_duration

    3. `download_video(video_url: str, output_dir: str, cookies_browser: str = "firefox") -> dict`:
       - Create output_dir if not exists (Path.mkdir(parents=True, exist_ok=True))
       - yt-dlp options: format (best mp4), outtmpl ({output_dir}/%(id)s.%(ext)s), writethumbnail=True, writeinfojson=True, cookiesfrombrowser as tuple, quiet=True
       - Return info dict from extract_info(video_url, download=True)
       - Wrap in tenacity retry (2 attempts)

    4. `process_discovered_videos(engine: Engine, settings: AppSettings) -> int`:
       - Query all Content with status=DISCOVERED
       - For each: get metadata, check should_download with per-channel or global max_duration
       - If should not download: log skip with duration info, leave as DISCOVERED (or mark as a skip -- use discretion)
       - If should download: transition to DOWNLOADING, call download_video, on success transition to DOWNLOADED (set video_path, thumbnail_path, downloaded_at), on failure transition to FAILED (set error_message, failed_at)
       - Update duration field from metadata
       - Return count of successfully downloaded videos

    Write tests with mocked yt_dlp.YoutubeDL. Verify cookiesfrombrowser is tuple format. Test duration filtering edge cases. Test state transitions with real SQLite (in-memory).
