    - test_job_replace_existing: Adding job twice with same ID does not create duplicate (replace_existing=True)
    - test_job_coalesce: Job defaults include coalesce=True and max_instances=1
    - test_recover_downloading: On startup, Content rows with DOWNLOADING status are transitioned to DISCOVERED (retry) or FAILED
    - test_poll_and_download_job: poll_and_download_job calls discover_new_videos for each channel then process_discovered_videos
  </behavior>
  <action>
    Create src/crosspost/scheduler.py with:

    1. `recover_incomplete_downloads(engine: Engine) -> int`:
       - Query all Content with status=DOWNLOADING
       - For each: transition to DISCOVERED (so they'll be retried on next poll)
       - Log recovery count
       - Return count of recovered items
       - Called once on startup before scheduler begins

    2. `poll_and_download_job(settings: AppSettings, engine: Engine) -> None`:
       - For each channel in settings.channels: call discover_new_videos(engine, channel)
       - Then call process_discovered_videos(engine, settings)
       - Log summary: channels polled, videos discovered, videos downloaded
       - Wrap entire function in try/except to prevent job crashes from killing the scheduler

    3. `create_scheduler(settings: AppSettings, engine: Engine) -> BlockingScheduler`:
       - Create SQLAlchemyJobStore with a SEPARATE SQLite URL for jobs (derive from settings.database_url by appending "_jobs", e.g., "sqlite:///crosspost_jobs.db")
       - Set job_defaults: coalesce=True, max_instances=1, misfire_grace_time from settings
       - Create BlockingScheduler with the job store
       - Add job: poll_and_download_job with IntervalTrigger(minutes=settings.schedule.poll_interval_minutes), id='youtube_poll', replace_existing=True
       - Pass settings and engine as job args/kwargs
       - Return scheduler

    Write tests:
    - Test scheduler creation and job registration (mock BlockingScheduler or use real with SQLite :memory:)
    - Test recover_incomplete_downloads with real in-memory SQLite
    - Test poll_and_download_job with mocked feeds and downloader functions
    - Verify replace_existing behavior prevents job duplication

    IMPORTANT: Use a separate SQLite file for APScheduler job store vs content DB to avoid lock contention (per research anti-pattern guidance).
